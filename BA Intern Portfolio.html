Two illustrative projects demonstrate how I would approach a business problem from discovery to requirements. They are portfolio simulations, not deployed products.

CASE STUDY 01 · HEALTHCARE

Clinic Appointment Booking

Design a clearer booking journey for patients and a manageable appointment workflow for clinic staff.

User storiesAS-IS / TO-BEUse cases

Problem framing

Simulation assumption: patients may struggle to find available slots, while staff may need to handle duplicate requests and last-minute changes manually.

BA deliverables

01 · StakeholdersPatient, receptionist, doctor
02 · Process mapCurrent vs proposed flow
03 · User storiesGoals + acceptance criteria
04 · Edge casesCancel, reschedule, conflict

Example user story

As a patient, I want to view available appointment slots so that I can choose a time that fits my schedule.

ⓘNext step: validate assumptions with sample interviews and test whether the proposed flow reduces booking friction.
CASE STUDY 02 · E-COMMERCE

Order Tracking & Returns

Map the post-purchase experience and clarify the rules for order status, cancellations, and return requests.

Business rulesAcceptance criteriaKPIs

Problem framing

Simulation assumption: customers cannot easily understand delivery status or return eligibility, generating avoidable support questions.

BA deliverables

01 · Status modelPlaced → shipped → delivered
02 · Business rulesReturn window and exclusions
03 · Exception flowsFailed delivery, cancellation
04 · Success metricsContact rate, return completion

Example acceptance criteria

Given an order has shipped, when the customer opens order details, then the latest available shipment status and its timestamp are displayed.

ⓘNext step: define status ownership and data refresh expectations with operations and engineering stakeholders.
